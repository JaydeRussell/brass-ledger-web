## Method

- **Real app, real gate.** Local Docker stack with a seeded, approved admin session linked to your BCP profile (on LVO 2026, 678 players, and the Denver Oct. Open), plus an unlinked "fan" account for spectator flows. Live BCP data throughout.
- **Mobile by emulation.** Playwright 1.63, WebKit and Chromium, at 320, 390 and 1280 px; touch forced (`hasTouch`, plus `isMobile` in Chromium); Compact/Roomy density with XL text; geolocation emulated for Near me; Slow-connection emulation (2 s latency, 400 kbps); outages by aborting every API request. The app is dark-only, so there was no second theme to set.
- **Production, read-only:** every route's status, compression headers, request counts on the event page from your browser session, and post-deploy checks of each fix.
- **What it cannot see:** a real phone (iOS share sheet behaviour, the iOS location prompt, Dynamic Type on device); real touch events (synthetic taps differ); Safari's first-share fallback; the local stack runs `next start`, not vinext (C13), so production-only differences were checked against production or a local `wrangler dev` of the vinext build.
- **Defects in my own tools:**

  - T2: the new route smoke failed the v0.28.1 deploy on one transient 503 during rollout; it now retries twice.
  - T3: an unreachable host printed `000000` and passed the smoke; now it fails.
  - T5: the changelog page test rejected any release title containing an apostrophe (React escapes it); it forced a reworded v0.26.0 title and failed again on v0.28.3. Fixed in the test.
  - T4: the grand-hunt skill's `memwatch.sh start` launches its sampler with `nohup … &` inside a shell command; this harness ends such jobs, and sampling stopped at 03:24:09 (18 samples). The `memwatch.sh check` before every heavy step still ran (31–45% free throughout). Fix in the skill: start the sampler with the Bash tool's background option.
