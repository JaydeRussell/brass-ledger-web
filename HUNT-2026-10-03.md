## Method

- **Drove the real app through the real gate.** Local Docker stack,
  signed in with a seeded session for an approved admin linked to a real
  BCP profile, against live BCP data. The main test event was LVO 2026:
  678 players, 652 placings, 10 rounds. Production was read for data
  sizes, and its public pages under throttling.
- **Mobile by emulation.** Playwright 1.63 with WebKit and Chromium, at
  widths 320, 360, 390, 430 and 1280. `hasTouch`/`isMobile` were forced
  for touch checks, and both themes were set explicitly. The on-screen
  keyboard was approximated by a 390×420 viewport, the network by CDP
  throttling (Fast and Slow 3G), and outages by aborting every request
  to the API.
- **Measured, not eyeballed.**
  - `scripts/audit/probe.js` counts horizontal overflow, small targets,
    low contrast, missing alt text and unlabeled controls.
  - `scripts/audit/sweep.mjs` runs the probe over routes, engines and
    widths.
  - `scripts/audit/outage.mjs` checks every signed-in page with the
    backend down.
  - Go tests count round trips; mutation checks confirmed that new tests
    fail without their fix.
- **Read-only agents** verified the remaining W-B and API-B assumption
  rows against the code (with file:line evidence). Each finding was then
  reproduced or reasoned through before being fixed.

**What the method cannot see.**
- Emulation is not a device. iOS Dynamic Type, Android text scaling, the
  real on-screen keyboard's visual-viewport behaviour, and the popup
  sign-in hand-off on an installed iPhone app (W-B70) were all unreached.
- Synthetic taps aren't real touch.
- No live team event existed, so team board paths are unverified.
- Locally, the server-side `/api/me` lookup always fails, because inside
  the frontend container `localhost:8080` is the container itself. Local
  runs therefore always take the client-lookup path that production
  takes only on a cold start.
- Docker builds with `next build`, while production uses vinext. CI now
  builds both (BUG-18), but local browser checks run the `next` build.

**Defects in my own tools** (logged as findings):
1. Integration tests migrated the shared dev database, which hashed
   every local session and made the first sweep run signed out.
2. The probe read `innerText`, which reported 72 hidden links as
   unlabeled; it now uses `textContent`.
3. `run.sh -d --build >/dev/null` hid a failed `next build`, so the old
   container kept serving and one measurement was of stale code. Rebuilds
   now print errors and the container's start time is checked.
4. The probe runs at page load, so controls inside closed menus and
   unopened modes went unseen (BUG-51 found six there).
5. I caused one regression myself, a round-0 note request (BUG-45). The
   320px sweep caught it before release.
